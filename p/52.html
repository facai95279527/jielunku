miai 分析

本文以 miai/facts.md 中已核实事实为依据，必要时核对 论文原文。事实抓取日期为 2026-10-26（新加坡时间）。工程判断、建议与尚未核实的事项分别说明；不把斗地主结果当成掼蛋结果。

1 结论摘要

miai 值得我们当作强陪练、人工对照和工程方法参考，但现有证据不足以证明其掼蛋算法在相同规则、相同算力下优于我们的 DouZero 式 DMC。论文中的 VRPO 在斗地主上明显胜过 DouZero；论文全文没有掼蛋实验数据，也没有人类对战测试。

对目前只有 8 核 CPU、15GB 内存、无 GPU 的工具，建议继续以 DMC 为主线，先借鉴动作拆分思路、终局奖励、复式牌评测与 Edge 对照指标。VRPO 整体替换涉及训练体系重构，暂不建议；可列为后续 GPU 阶段的候选方案。

网站可以先用于免费陪练和人工对照。自动接入前应联系作者，询问 /api/act 是否可授权使用；接口存在、前端能调用，并不等于公开授权。当前未发现可直接下载的代码或权重。

Botzone 掼蛋天梯的第 3 名 miai，作者为 nanomena，分数 1220.25，描述链接指向 guandan.miai.moe 和论文。GitHub 身份对应 Zhiyuan Fan（范致远），MIT 博士生；个人主页还列有斗地主与桥牌网站。

同一天梯另有第 18 名 miai_vrpo（开心掼个蛋，1148.10，描述为“VRPO self-play”）和第 11 名 miai（Caelum，1183.57）。它们与 nanomena 的关系查不到，不能混作同一模型或同一作者的成绩。

论文为 Zhiyuan Fan、Gabriele Farina 合著的《GAE Falls Short in Imperfect-Information Self-Play Reinforcement Learning》，arXiv:2605.19235v1，2026-05-19 提交，是预印本，未注明录用会议。主页上的其他研究和报道可以辅助确认作者身份，不能代替掼蛋实力证据。

3 论文方法通俗解释
# VRPO / Q-boosting

VRPO 是 PPO 的改版。PPO 可以理解为“根据这批对局调整出牌倾向，但限制每次改动幅度”。论文关注的问题是：传统 GAE 用实际发生的后续行动估计当前动作好坏；自对弈策略带有随机性，后续抽样出什么动作会给这个估计带来噪声。即便局面价值预测完全准确，这种噪声仍然存在。

Q-boosting 训练一个中心化 Q-critic，预测“当前局面下，每个候选动作分别值多少”。训练时它能看全部玩家手牌，用多步 Expected SARSA(λ) 迹替代 GAE，把部分后续动作的随机抽样换成按策略概率求期望。λ=0.95；论文定理在 λ=1 时给出无偏性质，并说明 critic 足够准确时，其均方误差小于使用精确局面价值的 GAE。这有条件限制，不是任意训练阶段都保证更优。

训练保留 PPO clip，ε_base=0.02；加入到均匀分布的 KL 正则，α_base=0.1 并衰减，以维持探索；critic 使用 64×B 的小循环回放；评测使用 β=0.999 的策略 EMA，可理解为对近期策略做平滑。

训练时看全手牌、执行时只看本方信息，属于中心化训练、分散执行（CTDE / MAPPO 式）。这不意味着部署时能偷看对手手牌。

# 网络

观察先变成 token，使用 128 维嵌入求和，加玩家嵌入，再送入 4 层、4 头的 LLaMA 式因果 Transformer，前馈层倍率为 2；之后拼接二值通道，经过带 RMSNorm 的 3 层、256 宽 MLP。通俗地说，它把牌、玩家和出牌历史编码成一个局面特征。

候选动作使用 256 维 token 嵌入和 2 层 MLP，与局面特征做内积，得到动作偏好。critic 对每个玩家分别编码，再用残差 MLP 融合，输出各候选动作的 Q 值。优化器为 Muon，学习率 4e-4，权重衰减 0.01。论文各游戏使用同一结构和超参数；网站掼蛋部署的具体网络和训练配置查不到。

# 动作拆分

一次完整出牌可以拆成连续的小选择：先选牌型和主点，再选终点或带牌。这样不用同时给所有完整组合打分。论文斗地主单步最多 35 个候选，对比 DouZero 的 27,472。

这是表示方法上的节省，但选择步骤会变多，且前面的选择影响后续可选项。掼蛋还涉及逢人配和不同牌型，不能直接沿用斗地主编码，也不能把这些候选数当作掼蛋数据。

# 奖励与无搜索

论文只用终局奖励，斗地主按炸弹翻倍计分，不依赖人工设计的辅助损失。其思路是让模型最终对赢输或计分结果负责，而不是人为规定“某种出牌看起来更好”。迁移到掼蛋时，仍须先确定头游、搭档结果和升级收益之间的目标口径。

论文方法没有在线搜索，也没有独立的对手手牌推断模块；部署决策依靠策略网络。无搜索可以减少决策时的计算，但不代表训练便宜，也不代表没有从历史信息学习对手牌的隐含判断。

我方为 8 核 CPU、15GB 内存、无 GPU。论文斗地主的 55 小时是大规模 GPU 训练的实测结果，既不是掼蛋训练时间，也不是 CPU 运行时间。

CPU 大约差几个数量级：现有事实查不到，无法给出有证据的数量级估计。 GPU 数量与 CPU 核数不能直接相除；训练还包含环境采样、网络更新、批处理和内存开销。按工程判断，同等规模训练在我方机器上会有显著资源压力，但具体慢多少不能量化。

可执行的估算办法是：先让相同配置的小规模原型在我方机器上完成包含采样与更新的完整训练循环，测得有效训练步吞吐，再以论文约 2.65e9 步除以吞吐估算 CPU 时长，并与 55 小时比较。该结果仍应标为估计，因为短程吞吐未必代表长期运行，且动作拆分后的“步”必须使用一致定义。当前没有这项实测；在“只用 facts 数字”的约束下，不编造百倍或千倍差距。

斗地主表格是角色平均收益，不是胜率，不能改写为胜率提升。±1 SEM 也不能当作 95% 置信区间。论文报告 VRPO 约用 40% 的训练步数便超过 PerfectDou；DouZero 的训练量约为 1e10 步。这支持其在该实验设置下的样本效率优势，不构成我方掼蛋训练的耗时保证。

复式牌的价值在于让不同策略在相同发牌条件下比较，减少发牌运气对差异的干扰。论文没有人类对战测试。

9 具体建议
  • 先用网站做免费的强陪练和人工对照。 记录典型局面、合法动作、我方 wp/adp 排序及实际结果；把差异当作待验证假设，避免凭少量输赢下结论。
  • 联系作者询问 /api/act 是否可授权使用。 同时确认模型版本、规则、调用协议和使用限制。在授权明确前，不擅自调用未公开接口。本报告不代为发送联系消息。
  • 优先建设复式牌评测和 Edge 类对照。 固定发牌与版本，让候选策略和基线在同样条件下复打；同时报告样本量、收益和误差。先使用我方明确的头游目标，完整升级赛指标待规则补齐后再做。
  • 核对终局奖励。 明确当前优化的是头游还是搭档收益，使训练目标与评测目标一致；不直接照搬斗地主炸弹翻倍奖励。
  • 把动作拆分作为独立工程试验。 先证明合法动作覆盖和回译正确，再测候选评估开销与完整决策耗时；候选数减少不等于总耗时必然减少。
  • 保留 DMC 主线，暂不整体替换为 VRPO。 后续具备 GPU 条件时，再评估中心化 Q-critic 和 Q-boosting，并用相同规则与复式牌比较实际收益。CPU 阶段若做原型，目的应是验证正确性与测吞吐，不承诺论文级训练结果。
