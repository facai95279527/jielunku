外盘黄金 → 国内 518880 联动自动交易系统

不是投资建议。 本项目是工程脚手架，用于验证「外盘金价短时方向 → 黄金 ETF 518880 买卖」的流程。是否有效、能否覆盖成本，必须由你自己用 paper 和小资金验证。文中未给出任何实测延迟或相关系数。

1. 架构
           ┌────────────── 外盘行情（多源 failover）──────────────┐
           │ TwelveData WS/REST │ GoldAPI │ Polygon(Massive) │ Yahoo(延迟,仅fallback) │
           └──────────────┬──────────────────────────────────────┘
                          ▼
 AKShare 518880 价/IOPV/折溢价 ──► 信号 LinkageSignal ◄── AKShare 汇率 USD/CNY(CNH)
                          │  短窗收益率 + 确认N tick + 冷却 + 延迟补偿 + 折溢价过滤
                          ▼
                    风控 RiskGuard（时段/单笔/持仓/次数/断流熔断/T+1）
                          ▼
             Broker：PaperBroker(data/*.csv|jsonl)  或  QmtBroker(xtquant → MiniQMT)

  • 腾讯云 Linux 适合 7×24 跑信号与 paper 验证（systemd 守护）。若要云端信号远程触发本地下单，需要自建可靠通道（鉴权、去重、过期丢弃），本版本未内置该通道，只把信号写入 data/signals.jsonl；推荐直接用方案 A，少一跳延迟和故障点。

4. 配置要点（config.yaml）
项 说明
mode connectivity / paper / live，默认 paper
enable_live + live_confirm live 双开关：true 且 "I_UNDERSTAND_REAL_MONEY"，缺一拒绝启动
overseas.sources 尝试顺序；live 模式自动剔除 yahoo
overseas.stale_after_sec 非 Yahoo 源超过该秒数视为过期并切源
signal.window_sec / buy_threshold_bp / sell_threshold_bp 短窗收益率阈值（bp）
signal.confirm_ticks / cooldown_sec 防抖动：连续 N 个新 tick 同向才出信号；信号间冷却
signal.latency_comp_sec 延迟补偿（秒），默认 0；只有实测出稳定时滞再调
signal.max_premium_buy_pct / min_discount_sell_pct 溢价过高不追买、折价过深不杀跌
risk.* 单笔金额、持仓上限、日内次数、断流熔断秒数、交易时段
broker.qmt.userdata_path / account_id MiniQMT 的 userdata_mini 目录与资金账号
# 外盘源延迟档位

均以供应商文档与你购买的套餐为准，本项目未实测，需自备 key 实测：
- TwelveData：XAU/USD，WebSocket 推送需对应套餐；REST /price 可短轮询（受积分/频率限制）。
- GoldAPI.io：现货 REST，免费额度小，适合低频对照。
- Polygon（现 Massive）：C:XAUUSD 报价，需外汇/贵金属套餐（已实现 REST，未实测）。
- Yahoo GC=F：有延迟，只作 fallback/对照，live 下禁用。
- 更低延迟（CME 直连、券商期货行情、彭博/路透等）需另购并自行实现 Feed 子类（实现 latest() 返回 Quote 即可）。

6. 守护与异常恢复
  • 进程级：Linux systemd/supervisor，Windows NSSM 或任务计划（见 deploy/）。
  • 程序内：单次行情失败只告警；主循环异常指数退避（1→60s）；任一行情过期超 feed_stale_halt_sec 熔断不下单；TwelveData WS 自动重连并在断开时退回 REST；MiniQMT 断开后下单前重连 3 次；Ctrl+C / SIGTERM 优雅退出。
7. 风险提示（请逐条读）
  1. 延迟 ≠ 可套利。 外盘先动、518880 后跟的现象即便存在，也可能被做市商/其他程序在你之前吃掉；行情源延迟、AKShare 网页接口延迟（数秒级、不稳定）、下单链路延迟叠加后，优势可能为零或为负。
  2. 滑点与成本：ETF 买卖价差、佣金、冲击成本；频繁交易会迅速吞噬收益。
  3. 时段错配：外盘近 24 小时交易，518880 仅 A 股时段交易；隔夜/午休的外盘变动在开盘时一次性体现，系统不在非交易时段下单。
  4. T+1：518880 当日买入次日才能卖（系统按券商可用持仓判断）。
  5. IOPV 偏差：IOPV 本身由行情商估算、有更新频率，折溢价过滤只是参考。
  6. 监管与券商规则：程序化交易须遵守交易所程序化交易管理规定与券商要求（如报备、申报频率、撤单比例、异常交易监控）。QMT/MiniQMT 需在合法券商正规开户并开通权限，策略须合规；不要用高频报撤单、对倒、虚假申报等任何可能被认定为异常交易的方式。
  7. 数据源合规：AKShare 抓取公开网页数据，稳定性与使用条款以数据方为准；付费行情商的授权范围（个人/非展示用途）自行确认。
  8. 软件风险：代码可能有 bug；live 前务必读懂 signal/linkage.py、risk/guards.py，并从极小金额开始。
8. 测试
python -m pytest tests/ -q

9. 已知限制
  • 秒级外盘行情需付费 key，未在本环境实测任何延迟数值。
  • AKShare 接口字段/地址可能随版本变化；接口失败时明确报错不造数。CNH 目前用 CFETS USD/CNY 近似（日志 extra.proxy 标注），需真 CNH 请接离岸行情源。
  • 未内置 A 股节假日日历（周末已排除）；节假日 AKShare 无新数据会触发断流熔断，不会下单。
  • QMT 适配基于 xtquant 公开接口（XtQuantTrader.order_stock 等），未在真实 MiniQMT 上联调；首次 live 前请在券商模拟环境验证。
  • 云端→本地远程触发通道未内置。
