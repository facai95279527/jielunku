聊天原文 · 仓库分析（10-15 凌晨 3:0x）

new-term-radar（新词雷达）是个每天出报告的工具：在 AI 圈的新模型、新产品、新仓库刚冒头的时候就把名字抓出来，比 Google Trends、关键词工具早几天到几周。我读了它的中文说明，代码还没跑。

怎么抓
- 它盯的是新名字最早出现的地方：X 上关注的账号、Hugging Face 热门榜、GitHub 上星数暴涨的新仓库、竞品导航站新加的页面、刚注册的新站，还有你自己站的 Search Console 新词。
- 抓到名字后，它会找出背后大家真正会搜的通用词。比如 SynthID Detector 背后是「ai image detector」，大约每天 2,500 次搜索。然后估算搜索量、看 Google 首页还有没有位置，最后给出「优先、观察、跳过」三种决策。
- 每周还会读 Reddit 上「有没有 AI 工具能…」这类求助帖，和 TrustMRR 上已经有人付钱的产品（TrustMRR 是一个核验产品收入的网站），用来找真实需求。
- 每条线索 14 天后会回头对一遍 Google Trends，统计自己报得准不准、提前了几天。

成本：本体是纯 Python，只用标准库。免费的数据源（Hugging Face、GitHub、竞品站点地图）不要钱也能跑。完整用的话需要 AIsa 的 key，按示例配置大约每月 15 美元，另一个 GoAnyAPI 的 key 可选。

适合谁：做 AI 工具导航站、做 SEO、写 Newsletter，或者想抢在新词刚出现时就做页面、做产品的人。核心价值是信息差抢先。

局限
- 作者自己也说，对纯模型发布效果差，对只做一件事的产品和仓库效果好。
- 通用词会不会跟着新名字涨，还缺 14 天复盘的数据来证明。
- GoAnyAPI 是 2026 年 8 月才上线的服务，作者测试时每次调用要 20 到 55 秒，大约十次失败一次。
- 偏海外、偏英文搜索，对国内百度或微信的流量帮助不大。
- 说明里的 AIsa 和 GoAnyAPI 注册链接是作者的推荐链接。

对你的用处：跟你之前想做的每日新闻摘要、找信息差的方向很合。如果你想做 AI 工具内容或者站点赚流量，可以直接拿来用：先只跑免费的 GitHub 和 Hugging Face 信号，零成本，每天早上把新词发给你。要的话我可以在我电脑上搭起来，再做成每天自动跑的任务。

免费「有人付钱」路径（无 TRUSTMRR_API_KEY）
它是什么

没有 TRUSTMRR_API_KEY 时，信号 ⑥ 不会再关掉，而是自动走免费路径：

来源 要不要 key 给什么 是不是核验过的收入
Revmrr Open Data API 否（每月每 IP 约 100 条） AI 品类、MRR 在门槛以上且低于 max_mrr_usd 的产品 多为自报；revenue.verified 只在「单条详情」接口里，免费额度不够我们逐条打
Product Hunt Atom（AI 分类） 否 新上架的产品名 + 一句话介绍 不是收入，只是上架/兴趣代理
VerifyArr 公开 API 否 声称已核验的 MRR 列表 声称核验；目前库很小，经常几乎为空

有 TRUSTMRR_API_KEY 时，仍走原来的 TrustMRR 路径，免费路径不会掺进去。

它不是什么
  • 不是 TrustMRR 那种「从 Stripe / LemonSqueezy 等支付渠道读出来的 30 天收入」。
  • Revmrr 列表里的 MRR 不能当成已核验；大厂和自报数字都会出现。我们用 max_mrr_usd（默认 10 万）把超级大盘公司滤掉一些，方便看独立产品。
  • Product Hunt 只说明「有人在追这个发布」，不能说明有人付了钱。

若你要「支付渠道核验过的收入」，仍需自己去 TrustMRR 开发者后台 生成免费 key（tmrr_ 前缀）。本仓库不会替你申请或编造 key。

怎么跑
cd /workspace/new-term-radar
# 不要设置 TRUSTMRR_API_KEY
./run_daily.sh
# 或任意一天强制 ⑥：
python3 -m radar daily --revenue \
  --skip x,newsites,gsc,review,judge,usecases,asks,tutorials \
  --out reports/revenue-free-$(date +%Y-%m-%d).md
  • 默认仍只在 revenue.weekday（0=周一）跑，以省 Revmrr 免费额度。
  • ./run_daily.sh 只有在有 TrustMRR key 时才会每天强制 --revenue；无 key 时按星期几。
  • 快照存在 state/revenue_free.json.gz（与 TrustMRR 的 revenue.json.gz 分开）。
配置（config.json → revenue.free）
"free": {
  "revmrr_category": "Artificial Intelligence",
  "max_mrr_usd": 100000,
  "revmrr_limit": 10,
  "producthunt_category": "artificial-intelligence",
  "producthunt_max": 15,
  "use_revmrr": true,
  "use_producthunt": true,
  "use_verifyarr": true
}

署名与条款
  • Revmr：展示数据时注明 Data: Revmrr，并链到产品页；勿把自报当成已核验转卖。
  • Product Hunt：公开 Atom，合理使用。
  • TrustMRR：若用其 API，禁止转载数据做公开 SEO 页（原 README）。
